# Deploy with Cloudflare Workers

This repository uses Cloudflare Workers Static Assets. Only the files inside
`public/` are deployed:

```text
public/
├── index.html
├── style.css
└── img/
    └── profile-bacon.png
```

`README.md`, `docs/`, and other files at the repository root stay in GitHub but
are not part of the website. The boundary is declared in `wrangler.jsonc`:

```jsonc
{
  "name": "profile-card",
  "compatibility_date": "2026-08-01",
  "assets": {
    "directory": "./public/"
  }
}
```

There is no framework and no build step. Cloudflare documents static asset
requests as free and unlimited.

## Connect the GitHub repository

1. Push the finished page to the branch that will be used for production,
   normally `main`.
2. In the Cloudflare dashboard, open **Workers & Pages**.
3. Select **Create application**, then **Import a repository**.
4. Connect GitHub, authorize only the repositories Cloudflare needs, and select
   this repository.
5. Configure the Worker:

   | Setting | Value |
   | --- | --- |
   | Worker name | `profile-card` |
   | Production branch | `main` |
   | Root directory | repository root/default |
   | Build command | leave blank |
   | Deploy command | `npx wrangler deploy` |

6. Select **Save and Deploy**.
7. Open the generated `*.workers.dev` address and confirm the page, image, and
   links are present.

The dashboard Worker name must match `name` in `wrangler.jsonc`. To use another
name, change the configuration before importing the repository. After the Git
connection is active, pushes to the production branch deploy automatically.

Cloudflare may run a deployment when any repository file changes, but only
`public/` is uploaded as the website. Build watch paths under **Settings** >
**Build** can optionally limit which changes trigger a build.

## Use an existing `.cl` domain

The domain remains registered and renewed at NIC Chile. Cloudflare becomes its
DNS provider and connects it to the Worker.

### 1. Add the domain to Cloudflare

1. In the Cloudflare dashboard, open **Domains** and select **Onboard a domain**.
2. Enter the apex domain, such as `your-domain.cl`, and select the Free plan.
3. Review the DNS records Cloudflare found. Preserve every record used by other
   services, especially email records such as MX, SPF, DKIM, and DMARC.
4. Cloudflare assigns two nameservers. Keep the exact pair shown for this
   domain; nameservers from examples or another domain will not work.

### 2. Change the nameservers at NIC Chile

If DNSSEC is already active, remove or unpublish the old DS data at NIC Chile
before changing nameservers. An old DS record paired with new nameservers can
make the entire domain unreachable.

1. Sign in to the [NIC Chile customer panel](https://clientes.nic.cl/).
2. Open the domain and find **Servidores de nombre (DNS)**.
3. Replace the current nameservers with the two assigned by Cloudflare.
4. Save the domain update.
5. Wait until Cloudflare reports the zone as **Active**.

Cloudflare advises allowing up to 24 hours for a nameserver update. NIC Chile
notes that cached DNS information can take up to a couple of days to propagate
fully.

### 3. Attach the domain to the Worker

After the Cloudflare zone is active:

1. Open **Workers & Pages** and select `profile-card`.
2. Open **Settings** > **Domains & Routes**.
3. Select **Add** > **Custom Domain**.
4. Enter the apex domain, such as `your-domain.cl`, and confirm.

Cloudflare creates the required DNS record and HTTPS certificate. A Custom
Domain requires an active Cloudflare zone and cannot replace a conflicting
CNAME on the same hostname.

The temporary `*.workers.dev` address may remain enabled, but visitors can use
only the `.cl` domain.

### Optional: redirect `www`

Custom Domains match exact hostnames. To redirect `www.your-domain.cl` to the
apex domain, follow Cloudflare's redirect workflow: create a proxied placeholder
DNS record for `www` and a Redirect Rule from `www` to the apex. Cloudflare's
current documentation uses `192.0.2.0` as the originless placeholder IPv4
address.

### Optional: enable DNSSEC again

After the zone is active and the custom domain works:

1. Enable DNSSEC under Cloudflare **DNS** > **Settings**.
2. Copy the DS values generated by Cloudflare.
3. In NIC Chile, open the domain's **Servidores de nombre (DNS)** > **DNSSEC**
   form, choose **DS**, enter the values, publish them, and save the domain
   update.

Cloudflare cannot publish those DS values at NIC Chile automatically.
